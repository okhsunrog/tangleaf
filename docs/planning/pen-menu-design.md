## 0. Суть на одной странице

- Сток: до **5 слотов** («быстрых перьев») в верхней панели, каждый = тип + толщина в мм + цвет +
  чувствительность; первый тап выбирает, второй открывает меню; «+» копирует активный; удаление с
  подтверждением, минимум один слот (`SN/15` §1, §3) [код + снимок].
- Главная задача не меню, а **вид штриха после отрыва пера**. SurfaceFlinger (SF) рисует живой штрих
  своим движком по типу пера; у стока после отрыва ничего не перерисовывается, а при следующей
  передаче панели приложению его битмап нарисован **тем же движком `libneo_pen`** (§5.1). У нас после
  каждого штриха холст перерисовывает штрих **своей кистью** (`tangleaf-segment-v1`), и штрих
  заметно меняется (`hw/onyx-ink.ts:32-49, 362-397`; `docs/planning/ink-format-v1.md` §4: «Fast BOOX
  Fountain — временный preview») [код].
- Формулы «давление → толщина» всех перьев стока лежат в нативной библиотеке, в Java их нет
  (§5.1) [код]. Значит точное совпадение можно получить только измерением на книге (стадия 0) или
  нативным рендером через SDK, который мы уже линкуем (`libneopen_jni.so` в нашем APK, §5.4).
- Рекомендация: **стадия 0 — замеры на книге без кода**; **стадия 1 — слоты, один тип «Pen» с
  толщиной в мм и цветом, чувствительность фиксирована 30 %**; **одна ревизия формата** с набором
  кистей (Pen с параметром чувствительности, Ballpoint, Marker, перо с наклонённым срезом) вместо
  четырёх flag day; типы появляются в меню по мере того, как наш холст умеет их рисовать.

**Каждый тип помнит свою толщину** (`penWithMap`, с блокнотом) [код].

- **мм → px:** `px = мм × densityDpi / 25,4`; на книге 300 dpi → 1 мм = 11,811024 px. В SF уходит
  `min(px, mmToPx(max)) × pageScale`; в записи `pageScale = 1755/1860 = 0,9435`, 0,70 мм → 8,267717
  → `SET_STROKE_WIDTH 7,80099` (`SN/15` §7.4) [код + лог]. Толщина пера — величина **на странице**;
  у ластика — на стекле (`SN/12` §6.5) [код].
- **Давление** (только Pen): 0–100 % шагом 10, по умолчанию 30 %, 0 показывается как `OFF`. В SF:
  `SET_STROKE_PARAMETERS(1, [p, 0,6])` при каждом resume, при открытом меню — ничего (`SN/15` §8.1)
  [код + лог `A1:207-208`]. Что SF делает с параметром — **[неизвестно]** (`SN/15` §15 п. 4).
- **Стабилизация** (0,6) на этой модели скрыта, но посылается (`SN/15` §8.2) [код + лог].
- **Цвета:** 16 фиксированных, без своих: Black `FF000000`, Dark Gray `FF404040`, Medium Gray
  `FF808080`, Light Gray `FFC0C0C0`, White `FFFFFFFF`, Red `FFFF6163`, Green `FF00B036`, Navy Blue
  `FF000084`, Aqua Blue `FF00F0FF`, Violet `FFEE00FF`, Orange `FFFFAA00`, Lemon `FFF0FF00`, Chartreuse
  `FF008000`, Grape `FF9338BE`, Sky Blue `FF00AAFF`, Orange Red `FFFF4400`; подпись
  `Red(#FFFF6163)`; на белом/красном/зелёном/синем кружках буквы WT/RD/GN/BU (`SN/15` §9) [код +
  снимок].
- **Что и когда уходит в SF из меню** (`SN/15` §10.2): тип/цвет — `SET_STROKE_STYLE`/`_COLOR` сразу
  (перо на паузе); толщина — `SET_STROKE_WIDTH` сразу, немасштабированная; полный правильный набор —
  при resume через **500 мс после закрытия** [код + лог].
- **Закрытие меню:** тап снаружи, второй тап по слоту, OK в диалоге удаления. Выбор типа, цвета,
  толщины меню **не закрывает** (`SN/15` §11.1) [код]. При закрытии одна частичная перерисовка
  REGAL_PLUS, как у ластика (`SN/12` §9.2) [код + лог].

## 3. Слоты в панели инструментов

### 3.1 Модель

```
PenSlot  { id, type: "pen" | "ballpoint" | "marker" | "brush" | "pencil",
           nib?: "pen" | "calligraphy" | "fountain",      // только type "pen"
           texture?: 1 | 2,                               // только "pencil"
           width: сотые мм (10…200; marker 50…800, шаг 5),
           color: индекс 0…15 палитры стока,
           pressure: 0…10 (× 10 %) }                      // только "pen"
PenSlots { slots: PenSlot[1..5], selectedId, widthByType: Record<type, сотые мм> }
```

- Тот же приём, что `hw/eraser-settings.ts`: целые сотые мм на сетке 0,05, `normalize` при `merge`,
  ключ `tangleaf.pen-slots.v1`. Толщина типа помнится в `widthByType` (аналог `penWithMap` стока).
- Цвет — индекс в палитре, а не ARGB: своих цветов у стока нет (`SN/15` §9.3) [код], а индекс
  переживёт смену чёрного `#111111` → `#000000` (§6, вопрос 9).
- Активный слот **применяется сразу** при тапе (как сток: пауза, стиль и цвет, resume) — это один
  `configure` плагина, как сегодня смена толщины (`hw/onyx-ink.ts:182-254`). Изменения в меню
  применяются **при закрытии**, как у ластика (`hw/handwriting-note-view.tsx:448-455`), потому что
  каждое применение = пауза/resume пера.

### 3.2 Эскиз панели (книга, портрет, 661 CSS px, панель 44 px)

Сегодня правый кластер (ластик … More, зазоры 4, разделители 5) занимает 278 CSS, кнопка Pen стоит

## 5. Как рисуется каждый тип: SF, битмап стока, наш холст, формат

### 5.1 Общее

- **Живой штрих** рисует SF своим движком; нативная библиотека `libneo_pen` статически вшита в
  `surfaceflinger` (одни и те же строки `neopen_createPen`, `neo_pen_export.cpp`,
  `neo_charcoal_pen_v2.cpp` в обоих бинарниках) [вывод]. Стили `SET_STROKE_STYLE`: PENCIL 0,
  FOUNTAIN 1, MARKER 2, NEO_BRUSH 3, CHARCOAL 4, DASH 5, CHARCOAL_V2 6, SQUARE_PEN 7
  (`NA/sdk/pen/TouchHelper.java:23-30`) [код].
- **Битмап стока** после отрыва: `shape.lowLatencyRender` → те же нативные перья через JNI
  (`NA/sdk/pen/NeoPenNative.java:22`: `System.loadLibrary("neo_pen")`; типы BRUSH 1, FOUNTAIN 2,
  MARKER 3, CHARCOAL 4, CHARCOAL_V2 5, FOUNTAIN_V2 6, PENCIL 7, BALLPOINT 8, SQUARE 9,
  `NeoPenConfig.java:22-30`) [код]. Вход: `{x, y, pressure/max, size, tiltX, tiltY, t}`
  (`NA/sdk/pen/utils/PenUtils.java:155`); выход трёх видов: `PenPointResult` — точки с размером,
  рисуются `drawLine` с `strokeWidth = size` и круглыми концами; `PenPathResult` — замкнутый контур,
  `drawPath`; `PenTextureResult` — штампы-битмапы (`PenPointResult.java:103-117`,
  `PenPathResult.java:179, 264`, `PenTextureResult.java:94-99`) [код].
- **Кривые «давление → толщина» целиком нативные**; в Java их нет (символ
  `FountainPenWidthCalculator` в библиотеке) [код + неизвестно]. Значит подогнать нашу кисть можно
  только по замерам на книге (стадия 0) либо дизассемблированием `libneo_pen.so`
  (`~/tmp_zfs/onyx_framework/native/libneo_pen.so`).
- Даже у стока живой штрих и битмап **не обещаны попиксельно равными**: приложение заново гонит
  нативное перо по сохранённым точкам с другими входами, а для Pen прибавляет к ширине
  `3,0 / createScale` (`FOUNTAIN_PEN_V1_COMPENSATION`, `NA/sdk/pen/utils/FountainShapes.java:22-33`)
  [код + вывод]. Стоку это не мешает, потому что панель на этой книге показывает битмап только при
  hand-back (меню, смена инструмента), а не после каждого штриха (`SN/02` §1.6, §5.6) [код].
- **Цвет**: у стока в SF и в битмап уходит сырой ARGB на цветной панели, на моно — не-серый → чёрный
  (`NA/sdk/scribble/shape/RenderContext.java:357-363`; `SN/02` §6.3) [код]; подробнее §6.
- **Наша кисть** `tangleaf-segment-v1`: диск в P0, затем на каждую пару точек отрезок постоянной
  толщины `base_width × (0,25 + 1,5 × p̄)` с круглыми концами, каждый примитив композитится отдельно
  (`ink-format-v1.md` §4) [код]. Структурно это то же, что `PenPointResult` стока: **отличается
  только функция толщины**.

## 6. Цвет на панели Kaleido

- **Сток, живой штрих:** в SF уходит сырой ARGB, потому что `isColorStrokesShowOriginal()` по
  умолчанию = `isColorDevice()`; в записи красный `-40605 = 0xFFFF6163` (`SN/02` §6.3; `SN/15`
  §9.3; `A1:195-196`) [код + лог]. Показывает ли панель живые чернила в цвете — **[неизвестно]**
  (`SN/02` §1.9, эксперимент 11.6 не проводился). В стоке след мягкого ластика на книге виден
  «в цвете» (`SN/11-observations.md:103-105`) [снимок пользователя, косвенно].
- **Сток, битмап:** тот же `getRenderColor`: цветная панель — как есть; моно — не-серый → чёрный с
  альфой исходного (`RenderContext.java:357-363`, `PenUtils.java:56-61`); ночная тема меняет только
  чёрный↔белый; альфу добавляет один маркер (128) [код].
- **Панель:** Kaleido 3 — цветной слой поверх монохромного, по общедоступным характеристикам вдвое
  ниже по разрешению и блёклый; на книге не измерялось ❓. Светлые цвета стока (Lemon, Aqua) на
  такой панели едва читаются — сток их всё равно предлагает.
- **У нас:** штрих без цвета, `INK_COLOR = #111111`; профиль «mono» переводит цвет в серый по
  яркости (`hw/ink-model.ts:52, 58-75`); «mono» включается автоматически только если плагин сказал
  `colorPanel === false` (`src/app/display-profile.ts:60`) [код]; решение 2026-09-06: на e-ink цвет —
  сигнал, mono — явный режим для моно-панелей, серый по яркости (память `eink-display-profile`).
- **Предложение:**
  1. цвет штриха = ARGB из палитры стока, в `StrokeVersion.rgba`; DTO `InkStroke.color`; адаптер
     принимает 16 значений (+ старое `[17,17,17,255]`);
  2. `SET_STROKE_COLOR(argb слота)` вместо `INK_BLACK` (`kt/PenSettings.kt:33, 135`); в
     `OnyxInkArgs` — `strokeColor: Int`;
  3. холст рисует `rgba`; на «mono» — серый по яркости (наше решение), у стока — чёрный (вопрос 10);
  4. чёрный стока `FF000000` против нашего `#111111` — вопрос 9 (на e-ink любой серый дизерится, а
     `#111` — это серый на 7 %);
  5. кружки в меню — цветные диски; буквы WT/RD/GN/BU на четырёх исходных цветах, как у стока;
     полоска слота залита цветом и остаётся цветной при инверсии активного слота;
  6. на десктопе в тёмной теме лист всё равно белый — цвета без пересчёта.
