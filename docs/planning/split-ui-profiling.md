# Split: профиль интерфейса

Работа продолжает [release baseline](database-layer-baseline.md#итоговая-проверка-приложения-на-dab865c).
Цель — отделить доставку snapshot, React render/commit, создание и измерение CodeMirror,
измерение/прокрутку virtualizer, фокус и ожидание кадров в readiness probe.

## Два разных запуска

Обычная release-сборка с runtime inspection используется для сравнительных серий.
`tools/release-ui-probe.mjs` сохраняет прежний критерий: настоящий Split click, точный текст
сфокусированного видимого последнего редактора, затем ещё два RAF. Это наблюдение готовности,
не подтверждение показа пикселей дисплеем.

Отдельная диагностическая сборка включает React production profiling renderer и локальные
метки. Она не подходит для сравнения release p95: профилировщик и обёртки меняют стоимость
исполнения. Обычная сборка не включает profiling renderer и не собирает эти метки.

```sh
VITE_PROFILE_UI=1 vp run tauri build --no-bundle --features runtime-inspection --config src-tauri/tauri.dev.conf.json
```

Использовать отдельный профиль на копии базы. Через Tauri MCP установить неизменённый
`tools/release-ui-probe.mjs`, вызвать `arm` для проверенного исходного блока и числа частей,
затем установить `tools/split-ui-trace.mjs`. Открыть настоящее предложение Split и нажать
его кнопку через KWin MCP. До следующего действия сохранить результаты обоих probes.
После проверять точные Split/Undo/Redo и возвращать исходный блок. Между повторами trace
устанавливается заново после `arm`; `dispose()` восстанавливает изменённые методы.

## Что записывается

- `react.render`: actual/base duration и границы start/commit из React Profiler.
  Интервал start→commit сам по себе не равен CPU-времени render.
- `codemirror.state/create/focus/mounted`, а также diagnostic hooks методов
  `measure`, `update`, `requestMeasure`. Последние зависят от версии CodeMirror;
  отсутствие метода не превращается в поддельный нулевой замер.
- `outliner.flatten`, публикация children cache, layout commit; вызовы измерения
  и прокрутки virtualizer; отметки продолжения обработчика Split.
- Нативные DOM/Range geometry, focus и scroll calls, время запроса/исполнения RAF.
- Первое наблюдение строки, точного текста, фокуса и видимости целевого редактора,
  отдельно от окончания исходного readiness probe.

Синхронные spans включают вложенные spans: суммировать их как независимую работу нельзя.
React actualDuration также пересекается с измерениями внутри render. Задержка RAF не
доказывает длинную JS-задачу: нужны дополнительные данные для атрибуции browser/GPU/scheduler.
Наблюдатели сами читают layout и влияют на диагностический запуск. Часы WebView могут быть
дискретными; нулевой span означает «ниже доступного разрешения», а не отсутствие работы.

Collector ограничен 20 000 записями за окно в 5 секунд. Счётчики продолжают учитывать вызовы,
но отброшенные spans восстановить нельзя. Заметки не записываются в trace: исходный текст
используется только в закрытой переменной для точной проверки. Внешние артефакты содержат
идентификаторы объектов и технические метаданные, поэтому остаются вне Git.

Результаты и выводы добавляются после запуска диагностической сборки и проверки исходного
состояния/профиля; наличие инструментов само по себе не устанавливает bottleneck.
